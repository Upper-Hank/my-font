实施更新：根据后续“先做 MVP”的要求，已实现本地最短闭环。第一版使用 glyphsLib 直接生成 `.glyphs`，fontTools 生成原始候选的预览 OTF；人工微调后的正式字体仍从 Glyphs 导出。暂不实现本设计中的完整状态机、事务回执、独立几何校验点和自动发布。实际功能以 [README](../README.md) 与 [MVP 记录](mvp-status.md) 为准，下文保留为后续设计，不代表所有功能已完成。

## 1. 项目定位与结论

项目交付物是可以安装、输入、补字和持续微调的本人手写字体。你主要负责自然书写、判断字是否像自己、少量轮廓和间距微调；工程负责字表、模板、图像转换、导入、质量检查、版本和字体构建。

采用本地 Python 流水线 + Glyphs 3。第一版只有一个字重、一个 master、一字一形，优先中文，覆盖常用英文、数字及中英文标点。先交付小字库的完整闭环，再扩到 1000、3500 字。暂不做云服务、自建字体编辑器、AI 补字、手机自动采集、连笔识别和多字形随机替换。

保留笔迹的形状、相对大小、偏位和粗细变化，不自动逐字放大、居中或纠斜。但允许你有意识地调整字距、标点和个别轮廓；这些修改作为生产编辑保留，原始采集永久可追溯。普通单色字体不能保存纸张纹理、墨色透明度或每次书写的动态变化，也不能自动还原连续英文的所有连接关系。

当前目录只有研究报告，没有实现、扫描或样本字体，也尚未初始化 Git。本机发现 `/Applications/Glyphs 3.app`，读取版本为 **3.3**，项目及研究报告统一以 **Glyphs 3.3** 为目标版本。在 3.3 验证导入、保存、重新打开和导出。

## 2. 对研究报告的取舍

| 报告建议 | 实施决定 |
|---|---|
| 固定纸面坐标映射，不按墨迹 bbox 归一化 | 保留，为核心约束；补充基线、裁切偏移和统一比例的定义 |
| Python / OpenCV / Potrace / Glyphs | 保留；Potrace 用独立 CLI，避免旧 Python binding 成为阻碍 |
| 20 mm 格子、每页约 80 字 | 不直接锁定；大格会诱导写大字。先用自然样本选择尺寸，再由真实版面计算容量 |
| SVG 直接批量导入 | 需要实测；仅设置 viewBox 不能保证 Glyphs 不缩放、不平移 |
| CSV/JSON 是状态权威，Glyphs 是最终轮廓权威 | 明确拆开，并定义人工状态回传与冲突处理，避免两个系统互相覆盖 |
| background 同时存 raw trace 和旧轮廓 | 修正：background 只作当前原始轮廓参考；旧正式版本保存在项目快照中 |
| 四角标记 + homography 支持手机 | 标记可复用，但手机另列实验入口；透视变换不能修复纸张弯曲、模糊和局部阴影 |
| 首轮对比四套矢量算法 | 缩小：先验证 Potrace，只有具体失败样本才启用人工工具对照 |
| 扩到 6000 字主要是数量增长 | 加入返工比例和人工耗时门槛；流程不稳定时禁止扩大采集规模 |

## 3. 你实际使用的工作流

1. 工程生成本批 PDF 模板和对应字表；你打印、自然书写，扫描至收件目录。
2. 工程运行转换，得到带字符标签的整页核对图、待处理列表和 Glyphs 候选字形。
3. 你在 Glyphs 对照原图，使用三个入口：**通过、微调、重写**。阈值等转换异常由工程处理，不要求你调图像算法参数。
4. 工程合入通过的版本，导出预览字体和相同文本的排版样张。
5. 你查看整体大小、行距、字距和混排效果；工程处理全局参数，你决定视觉取舍。
6. 系统只为需要重写的字生成补写页，重复以上流程。

首版以本地命令和少量 Glyphs 菜单脚本实现。命令由工程维护，你不需要逐字管理文件、Unicode 或脚本。重写比修曲线省时的字直接重写。既有笔记先作风格参考；无模板的整页笔迹自动切字不纳入首版生产输入。

## 4. 架构与职责

```text
字表 + project.json
        │
        ▼
模板 PDF + 不可变 page manifest
        │ 你书写、扫描
        ▼
原始扫描归档 → 页面身份/几何检查 → 固定坐标切格
        ▼
灰度原图 → 二值图 → Potrace → 标准化路径 + SVG 预览
        ▼
候选包 + 质量报告
        ▼
Glyphs 脚本：候选层 / 原图参考 / 人工通过或微调
        ▼
正式 .glyphspackage 快照 → OTF → 检查 + 排版样张
        │
        └── 重写列表 → 补写模板 → 新候选 → 定向替换
```

| 模块 | 责任 | 交付 |
|---|---|---|
| 字表与模板 | Unicode 去重、缺字优先级、物理布局、页面身份 | PDF、page manifest |
| 扫描处理 | 归档、识别、校正、裁切、二值化 | 原图引用、每字 PNG、几何矩阵 |
| 矢量化 | 重复可执行的描边、坐标转换、异常检测 | 候选路径、SVG、QA 指标 |
| Glyphs 适配 | 导入候选、图片对齐、回传审核、冲突检查 | 人工可编辑的字体源文件 |
| 构建与补写 | 冻结版本、导出、覆盖检查、定向替换 | 字体、样张、补写页、构建清单 |

实现采用一个 Python 包，按上述职责分模块；无需服务拆分、任务队列或数据库。批次较小，先顺序处理；每字可断点续跑。依赖以 OpenCV、NumPy、Pillow、PDF/QR 生成库、fontTools 和 Potrace CLI 为限，具体版本在首个闭环通过后锁定。Glyphs 内脚本不导入 OpenCV 等外部处理依赖，只消费已验证的候选包。

## 5. 数据、版本与唯一权威

不要以 `uni4E2D.svg` 作为唯一存储路径，同一个字会重写、重新扫描和重新矢量化。

```text
project.json                     # UPM、比例、基线、流程版本
charset/                         # 阶段字表、个人测试语料
templates/<template-id>/          # PDF + 不可变 page manifests
scans/raw/<sha256>.<ext>          # 原始文件，只追加
samples/<sample-id>/              # page/cell/session/scan 引用
runs/<run-id>/<sample-id>/        # 灰度、二值、SVG、paths.json、QA
state/glyphs/<unicode>.json       # 当前候选、正式版本、审核结果
receipts/                        # Glyphs 导入、通过、补写操作回执
font/MyHandwriting.glyphspackage/
snapshots/<revision>/             # 完整字体源、状态快照与资源清单
builds/<build-id>/                # OTF、覆盖清单、检查报告、样张
src/handfont/                    # 本地转换工具
scripts/glyphs/                  # Glyphs 菜单脚本
docs/
```

三个权威边界：

- **采集事实**：不可变模板、扫描、sample manifest。页面与格子决定字符身份，不靠 OCR 猜字符。
- **流程状态**：`state/` 的结构化文件，只有本地工具写入；Glyphs 通过回执提交状态变更。
- **正式轮廓及字体参数**：`.glyphspackage`，构建时以冻结的源文件快照为准。旧候选不能覆盖人工结果。

最少数据字段：

| 对象 | 必需字段 |
|---|---|
| 页面 | project_id、template_id、page_id、schema_version、manifest_hash、尺寸、标记坐标、cell 列表 |
| 格子 | cell_id、Unicode、writing_box_mm、crop_box_mm、坐标配置版本 |
| 样本 | sample_id、page_id、cell_id、scan_hash、session_id |
| 处理 | run_id、sample_id、代码版本、工具版本、参数、输入/输出 hash、变换矩阵、QA |
| 字符状态 | Unicode、glyph_name、candidate_id、accepted_revision、review_status、reason |
| 回执 | operation_id、项目/master 身份、期望旧版本、实际新版本、相关文件 hash |
| 构建 | build_id、源快照 hash、状态快照、Glyphs 版本/build、导出选项、输出 hash |

`sample_id` 区分真实重写；相同样本不同转换参数产生不同 `run_id`。文件名称使用 Unicode 稳定 ID，Glyphs nice name 通过其字符信息接口匹配。首版一 Unicode 标量对应一个基本字形，拒绝重复映射；不偷偷将繁简、全半角或兼容字符合并。

每次写入先落临时文件，验证后原子替换；一个项目只允许一个转换写进程。重跑命中相同输入与参数时跳过。失败输出不能被标记为完成。恢复依据回执和文件 hash，不仅依据界面颜色。

Git 管代码、配置、状态和字体源；原始扫描放独立归档并做第二份备份。快照必须包含或明确引用可恢复的图片资源，不能只保存依赖本机绝对路径的 Glyphs 文件。首轮实际做一次备份恢复。

## 6. 采集与模板

先提供中文、英文和混排的自然样本各一小段，用同一支常用黑笔。对少量重复字符试两种接近日常书写尺度的模板，选更自然的一种。writing box 的大小不是让你把字填满；选择后冻结该 profile，避免批次间字面比例漂移。

模板约束：A4；四角不同 ID 的 ArUco 标记；独立 QR；字符提示在 crop 区域外；书写区内部无黑色格线。提示、角标与相邻字的 crop 区域不相交。PDF 生成时检查版面边界和区域碰撞，容量由布局实际计算。若参考线必须进入书写区，则先单独验证其去除方式，不能直接擦掉穿过线的笔迹。

QR 仅记录短页面身份和 manifest 指纹；详细几何由本地文件提供。身份不明、指纹不匹配或标记缺失的页面进入待处理区，不按文件顺序猜测。页面识别正确不代表填写正确：首轮及每个新批次都提供整页“提示字 + 实际笔迹”核对图，由你发现写错或串格。

生产输入先采用平板扫描、600 dpi、PNG/TIFF、关闭自动锐化和自动裁切，完整保留定位标记。同一批保持扫描配置一致。照片先归入实验路径；若缺少扫描设备，先用实际照片证明质量，再决定是否改变生产入口，不假定设备已经具备。

## 7. 坐标接口：必须可测量

UPM 初始设为 1000，中文 advance 初始设为 1000。字身底部初始设为 -120、顶部 880，作为待自然样本验证的初值，不是行业标准。字体行距还需单独设置 hhea / OS/2 等垂直指标，不能把字身范围直接当成最终行距。

设选定中文 writing box 边长为 L mm，统一比例 `s = 1000 / L`。经过页面校正，点的纸面坐标为 `(px, py)`（mm，向下为正）；writing box 左上角为 `(x0, y0)`：

```text
X = s × (px - x0)
Y = 880 - s × (py - y0)
```

边长 L=12 mm 时，右下角 `(x0+12,y0+12)` 映射到 `(1000,-120)`；左侧超出 writing box 1 mm 的笔迹映射为 X=-83.33，必须保留，不能为了限制在 em 内裁掉。

如果单字图片包含留白，从 crop 原点恢复纸面坐标后再套以上公式。像素转换使用实际校正画布尺寸和明确的像素中心约定，不依赖 PNG 的 DPI 元数据。PNG 参考图、二值图、路径三者共享同一变换。crop 触边即警告；不能无边界扩大裁切吞入邻格。

英文与中文采用相容的物理比例，以采集基线映射到字体 Y=0；英文比例若需调整，只允许显式 profile 级调整。英文初始 spacing 可以根据 ink bounds 建议左右留白并整体平移以建立左边距，不改变缩放及基线，并保存排版平移量。中文则保持固定字身坐标。英文 advance、space、中文标点宽度分别设定，不能全部强制 1000。

SVG 主要作预览和交换，工程内部同时保存已转为字体坐标的闭合路径（起点、直线、三次 Bézier、闭合标志）。优先验证 Glyphs 原生 SVG 导入；若发生无法稳定控制的缩放/平移，使用 fontTools 路径解析并通过 GSPath/GSNode 写入。只处理本项目 Potrace 产生的受限 SVG，展开其变换，不实现通用 SVG 渲染器。

校准使用离心矩形、带孔方框及越过字身边界的形状，分别检查 X/Y 方向、原点、比例、曲线与孔洞。背景图必须显式设置位置和比例，不能假设导入 PNG 自动与路径对齐。

## 8. 图像处理与异常分流

处理顺序：原件 hash 归档 → 识别模板 → 整页几何校正 → 固定坐标切格 → 保留灰度参考 → 批次统一阈值 → Potrace → 坐标转换 → QA。

默认不做形态学开闭、不按连通域大小删除小点、不自动修断笔、不简化到任意目标节点数。小点和孔洞可能就是字形。阈值覆盖只用于具体异常字，记录原因和参数。矢量化还原二值图的误差，与二值化相对原始灰度的损失分别检查，不能只看 SVG 是否漂亮。

| 故障 | 处理 |
|---|---|
| 页面 ID/模板不匹配、标记不足 | 阻断页面，工程修复身份或要求重扫 |
| 模糊、阴影、几何误差大 | 重扫，不能靠描边补救 |
| 空格或疑似串格 | 人工核对，标记补写 |
| 笔画碰 crop 边缘、混入邻字 | 核对原页，必要时重写 |
| 细笔画或小点丢失 | 工程调整阈值/trace 参数，生成新候选 |
| 自交、方向/孔洞异常、节点过多 | 工程修复或让你处理少量异常轮廓 |
| 字本身不满意 | 重写，不让你花大量时间重新描字 |

自动 QA 标识“需查看”，不把低墨迹面积直接等同空字。space 和规定的空白字符单列白名单。OCR 可作为以后发现疑似错字的辅助，不作为身份权威。

## 9. Glyphs 导入、人工编辑与补字

在已安装的 Glyphs 3.3 内验证脚本能力，记录精确 build。脚本确认项目 ID、master ID、UPM 和接口版本；不向碰巧打开的其他字体导入。

第一次导入进入候选/审核状态，图片放 backgroundImage，自动轮廓保留作参考。已通过字形的新 trace 只进入候选层，正式 foreground 保持原样。候选层是普通辅助层，不能误命名为影响导出的特殊层。

通过/替换操作按批次执行：

1. 保存并冻结当前源文件、状态和资源清单。
2. 生成替换清单，记录每个目标字当前轮廓、宽度等数据的指纹。
3. 再次核对实际数据；期间若你编辑过，判定冲突，停止替换该字。
4. 在字体工作副本应用指定候选，保存、重新打开验证，再作为新正式修订。
5. 生成回执，本地工具核对后更新状态。崩溃或回执缺失时先恢复一致性，不再次盲目导入。

微调后由“通过”脚本记录最新指纹；构建前重新检查是否存在未登记编辑。Glyphs 的颜色/tag 是界面提示，不能决定哪个轮廓已被发布。

状态最少为 `missing → candidate → review → accepted`；异常使用 `blocked` 或 `rewrite`。一个已通过字可以同时存在新的候选。补写只改变目标字，任何全局字距、feature、metrics 改动另作独立修订。撤销补写恢复对应目标的旧版本，不回滚期间其他字的编辑。

## 10. 构建与验收

第一输出为静态 OTF，TTF 在具体使用需求出现或 OTF 闭环完成后验证。Glyphs 作为首版编译器，在已验证的 macOS/Glyphs 环境运行；不承诺 Linux 无界面自动构建或跨版本逐字节一致。

预览构建可带缺字，文件名和报告明确标注覆盖范围。正式构建只包含通过审核的字形，以及 `.notdef`、space 等明确规定的工程字形；阻断重复 Unicode、意外空轮廓、损坏轮廓、缺失资源和未登记源文件变更。fontTools 检查 cmap、advance、命名与关键字体表。缺字不会悄悄塞入其他字体轮廓，覆盖报告区分已覆盖与系统 fallback。

样张使用固定个人语料，覆盖中文密集/稀疏字、英文大小写和下伸部、数字日期、中英标点、括号、重复字和多行混排。在 Glyphs 和至少一个实际目标应用中查看字距、行高、裁切及缺字。发布版本更新可识别的字体版本和内部名称，避免缓存导致误认旧版本。

只保留三个核心自动回归场景：

1. 坐标与身份：已知页面/校准形状经过裁切、描边、导入后，字与 Unicode 对应正确；放大、翻转、偏移能被检测。
2. 幂等与编辑保护：同输入重跑不重复导入；重新 trace 不覆盖人工修改；有冲突时拒绝替换。
3. 补字与恢复：替换两字后，其余字的轮廓、宽度、Unicode 和全局参数不变；中断及回滚后能够恢复一致状态。

以下是首轮工程目标，均需真实扫描校准后冻结，不能称为已验证保证：

| 维度 | 首轮门槛 |
|---|---|
| 模板/字符身份 | 本批零错配；不确定就阻断，不猜测 |
| 数字路径导入 | 校准位置误差 ≤1 font unit，验证数值变换，不含扫描误差 |
| 扫描几何 | 预留独立校验点，不只检查参与拟合的四角；初始目标 P95 ≤10 units、最大 ≤20 units |
| 细节保留 | 代表性小点、孔洞、细笔画人工核对无误删；自动指标只作辅助 |
| 人工负担 | 至少 80% 样本可直接通过或每字约 30 秒内完成微调；记录实际分布 |
| 版本保护 | 重跑零覆盖；补字零无关修改；恢复后源图引用有效 |
| 输出 | OTF 可导出、解析、安装并在目标应用输入；缺字与视觉异常有清单 |

如果人工负担不达标，先修改模板/扫描/阈值策略，不把问题留给你修 1000 个字。

## 11. 按交付推进的实施顺序

| 阶段 | 工程交付 | 你参与 | 进入下一阶段的条件 |
|---|---|---|---|
| A：接口先验证 | 10 个校准/样例形状的 Glyphs 导入、原图对齐、保存/重开、OTF 导出 | 提供一小段自然样本 | 当前 Glyphs 版本可完成往返，坐标无隐式归一化 |
| B：真实小闭环 | 约 80 中文 + A–Z/a–z/数字/所需标点模板、转换、核对图、预览字体 | 写字、扫描、判断像不像 | 几何和细节可接受，统计微调耗时 |
| C：可靠性闭环 | 重跑保护、异常队列、补写、回执、快照和恢复 | 重写两个字，微调一个字 | 旧微调不丢、只改目标字、可回滚 |
| D：日用版本 | 按个人语料逐批补到约 1000 中文，完善空格和混排 | 每批书写及审核 | 个人测试语料覆盖率达到共同选定目标，使用场景无阻断问题 |
| E：扩字 | 2500/3500，按实际缺字再决定更大字库 | 持续小批生产 | 前一阶段质量和人工耗时稳定 |

A–C 是一个完整首期，不能只打通“扫描到 SVG”就算交付。没有真实样本之前不对识别率、页吞吐或具体完工日期作保证。

粗略估算人的成本：若 1000 字平均书写 6 秒、平均审核 15 秒，仅这两项约 5.8 小时，还不含打印、扫描、返工和休息。这只是算例，阶段 B 实测后替换。后续每批建议按 15–25 分钟自然书写量安排，而不是硬凑页数。

规划的命令接口（尚未实现）：`handfont doctor`、`template`、`ingest`、`process`、`report`、`reconcile`、`patch`、`release-check`。Glyphs 内提供“导入候选”“通过”“标记重写”“导出预览”入口。先把这些做可靠，再决定是否值得增加图形界面。

开始实施时需确认的输入只有：自然样本、可用的打印/扫描方式、首个目标使用应用。默认简体中文为主，字表随个人语料调整；这些待确认项不阻碍先完成阶段 A 的坐标与适配验证。

## 12. 已核对依据与仍待验证事项

本方案结合仓库研究报告和以下一手资料作工程判断，网页核对日期为 2026-09-07。报告中的内部引用标记无法直接当成项目可追溯引用，因此保留实际链接。

- [Glyphs Python API](https://docu.glyphsapp.com/)：提供字形、图层、路径、背景图片等对象；文档提示 API 版本差异。支持能力不等于本机 3.3 的整个方案已验证。
