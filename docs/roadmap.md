# MVP 边界与后续规划

更新：2026-10-08。本文是当前范围决策；旧需求与实现记录中冲突的内容以本文为准。产品定位见 [字记是工具](direction.md)，不改变本文的功能边界。

## 当前优先级：打磨核心流程

主线为多元来源 → 统一转化 → 同一份字体的字符与字形管理。模板是可编辑的来源预设：指定模板预填区域与字符，通用模板预填区域；普通照片、扫描稿通过框选区域接入同一转化工作面。支持保存取字、修改预填字符、逐字与批量调整，入库后沿用多个字形的比较、选用与字体导出。

重点打磨完整字形占字面框的大小、等比缩放、居中和位移。保留原始轮廓，预览与导出使用同一修正参数。保持单人、本地、同一份字体；不引入多字体管理、部首拆分。自动切字、OCR、自由照片的透视校正尚未实现，后续依据真实素材决定。

## 第一版 MVP

保留字符库、模板和照片转换、候选确认、逐字和批量大小修正、字体预览与导出。
拆笔画及部件编辑明确延期，页面入口已移除，API 返回 410，原代码、数据许可证与历史测试隔离至 archive/strokes。已有用户数据不清理。

尺寸适配默认保留原稿。可选参考字面适配以 IBM Plex Sans SC 的同字符字面尺寸作为起点，保留手写宽高比；不支持的汉字、标点和拉丁字符不自动适配。整体缩放、居中和横纵位移可独立组合，修改作用于预览和导出，不覆盖原始轮廓。旧“统一最长边”仅兼容原有习惯。
这不是光学优化算法；参考字体风格可能不适合草书、瘦长体或特殊设计。后续需要参考字体选择、基准字组校准、类别化指标及实际段落对照；避免每字机械填满字框。

## 后续一：可往返的字体项目文件

计划私有扩展名 .myfont，内部采用 ZIP + UTF-8 manifest.json，复用标准容器以便维护。这是项目源文件，不等同于 OTF、Glyphs 或现有导出 ZIP；当前尚未实现。

内容包括 schemaVersion、项目标识和名称、字符及候选映射、当前采用项、原始矢量轮廓、修正参数、原始图片、模板及转换来源。所有资源使用相对路径，并记录大小与校验值。字体构建产物与可再生缓存不作为必需内容。MVP 不写入笔画编辑数据；将来扩展必须版本化。

导出时锁定一致快照；导入先校验版本、必需资源、字符映射与引用完整性，再建立独立项目，不覆盖当前项目。合并到现有项目作为另一个明确操作，逐项解决候选和默认字形冲突。
限制文件数、压缩前后大小，拒绝路径穿越、绝对路径、符号链接及异常压缩包。失败清理暂存内容并保持当前项目不变；未知版本明确拒绝。

验收：导出后在空工作目录导入，候选、采用项、来源和参数一致，生成字体轮廓一致；缺文件、损坏、冲突和恶意路径均不污染当前项目。

## 后续二：字符库统一导入入口

字符作为组织中心，照片转换只是来源之一。字符库提供“导入字形”，选择照片、SVG，未来可扩展字体文件或其他矢量来源。来源统一进入候选确认，不强制创建打印模板，不自动替换当前采用项。

SVG 首先支持单文件和多文件导入；单字入口预填字符，批量可用文件名或映射表识别 Unicode，无法识别必须人工指派。支持检查重复、缺少映射、空轮廓和超界，确认后加入候选。
第一阶段仅接受可解析的静态填充路径及确定性的几何变换；明确处理 viewBox、坐标反转、孔洞、单位和 advance width。文本、描边、滤镜等不支持项明确拒绝并提示转轮廓，不悄悄丢弃。拒绝脚本、外部资源和实体；限制尺寸及路径复杂度。

导入保留原文件、来源元信息和原始轮廓；复用统一修正、预览与导出流程。验收包含非零 viewBox、复合孔洞、变换、重复字符和不支持内容，预览与字体导出应一致。
